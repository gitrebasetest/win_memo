## Context

该变更面向 Windows 桌面场景，构建一个本地运行的备忘录工具。应用需要在常驻桌面和临时隐藏之间切换，提供快速录入带时间的事件，并在目标时间到达时以动画方式提醒用户。技术栈限定为 Python + PyQt6 + SQLite3 + PyInstaller，因此设计需要优先采用单机本地架构、Qt 事件循环驱动的调度方式，以及适合 Windows 分发的目录与打包方案。

## Goals / Non-Goals

**Goals:**
- 提供一个支持悬浮显示和隐藏切换的桌面主窗口。
- 提供事件的创建、编辑、删除、列表展示和时间排序能力。
- 提供基于本地时间的提醒调度，覆盖一次性提醒、按工作日提醒、按每周指定时间提醒和按绝对日期时间提醒。
- 提供提醒后的用户操作，包括关闭提醒和延后提醒。
- 提供工作日规则所需的节假日联网判断与本地缓存能力。
- 提供 Windows 开机自动启动、SQLite3 本地持久化与 PyInstaller 打包支持。

**Non-Goals:**
- 不支持多端同步或云端账户系统。
- 不支持按月、按年、Cron 表达式等更复杂的高级重复规则。
- 不支持多人协作、共享事件或远程通知。
- 不以系统级服务方式在后台常驻运行，初版仅依赖应用进程自身调度。

## Decisions

### 1. 采用 PyQt6 单体桌面应用架构
应用将采用单进程的 PyQt6 桌面架构，UI、提醒调度和数据访问都运行在同一个应用内。这样可以减少跨进程通信复杂度，并直接复用 Qt 的事件循环和动画能力。

备选方案是拆分为前台 UI 与后台守护进程，但这会增加进程管理、安装和打包复杂度，不适合作为首版方案。

### 2. 主窗口使用置顶无边框轻量面板，并提供隐藏入口
主窗口将采用轻量面板式设计，默认支持悬浮在桌面上方，并允许用户快速隐藏。隐藏后的恢复入口可通过系统托盘或快捷方式触发，以避免窗口丢失后无法找回。

备选方案是传统可调整大小主窗口，但这不利于“桌面备忘录”定位；只做托盘而不做悬浮面板又会削弱随手查看的体验。

### 3. 使用 SQLite3 存储事件、提醒规则和节假日缓存
数据层使用 SQLite3，保存事件标题、内容、提醒类型、一次性目标时间、星期规则、工作日规则、状态、最近提醒时间、延后到期时间等字段；同时增加节假日缓存表，用于记录联网获取的节假日与补班信息。SQLite3 足以支撑本地单用户场景，并且随 PyInstaller 分发更简单。

备选方案是 JSON 文件存储，但在规则查询、状态更新、缓存一致性和后续扩展上更容易出现问题。

### 4. 使用统一调度模型计算 next_trigger_at
提醒调度不直接只依赖单个目标时间，而是为每个事件维护可计算的下一次触发时间 `next_trigger_at`。对于一次性提醒，`next_trigger_at` 来自绝对日期时间；对于每周提醒，根据指定星期和时间计算；对于工作日提醒，结合节假日缓存判断下一个有效工作日。调度器基于 QTimer 周期性检查当前是否达到 `next_trigger_at`，触发后再计算下一次时间或标记完成。

备选方案是为不同提醒类型分别实现独立调度器，但会增加状态分散和维护成本。

### 5. 工作日判断通过联网节假日服务加本地缓存实现
工作日规则提醒需要识别法定节假日和调休补班，因此应用启动时或调度需要时联网获取节假日数据，并将结果缓存到本地数据库。调度优先使用缓存结果；网络不可用时可继续使用已缓存日期范围内的数据，避免基本功能完全失效。

备选方案是仅根据周一到周五判断工作日，但无法满足法定节假日和补班场景。

### 6. 提醒弹窗使用独立顶层窗口并加入轻量动画
到点提醒将采用独立顶层窗口显示，避免被主窗口隐藏状态影响。动画效果优先采用 Qt 原生属性动画，例如淡入、滑入或缩放，以保证实现简单和运行稳定。弹窗需提供“关闭”和“延后”两个明确操作。

备选方案是系统通知气泡，但交互能力有限，且动画样式受系统限制较大。

### 7. 延后提醒采用预设时间段
延后提醒首版使用预设时长，如 5 分钟、10 分钟、30 分钟。这样可以减少复杂输入和校验逻辑，提升提醒操作效率。后续若有需要，可扩展为自定义延后时间。

备选方案是允许任意时间输入，但首版会带来更多 UI 复杂度和异常场景。

### 8. 开机自启使用 Windows 登录启动机制
开机自启能力优先采用 Windows 用户级登录启动机制，例如注册表 `Run` 项或启动文件夹快捷方式，由应用提供开启和关闭入口。该方案不需要管理员权限即可覆盖大部分个人桌面使用场景。

备选方案是安装 Windows 服务，但这超出桌面提醒工具首版范围，也会显著提升安装复杂度。

### 9. PyInstaller 打包为单独可执行分发产物
打包方案采用 PyInstaller，输出适合 Windows 分发的可执行程序，并包含 Qt 运行依赖。数据库文件默认放在用户本地应用数据目录或可执行文件同级的应用数据目录中，避免升级时覆盖用户数据。

备选方案是仅以源码运行，不满足最终桌面工具交付需求。

## Risks / Trade-offs

- [应用未运行时无法提醒] → 提供开机自启能力降低遗漏概率；后续可评估后台服务。
- [QTimer 轮询精度受系统休眠或卡顿影响] → 使用较短轮询间隔并在恢复时补检查所有逾期事件。
- [节假日接口不可用或返回异常] → 优先使用本地缓存，并为缓存失效场景提供显式状态提示。
- [工作日定义存在地区差异] → 首版明确基于选定节假日数据源定义工作日规则，并在配置中预留后续扩展空间。
- [无边框悬浮窗口可能影响拖动与可发现性] → 提供明显拖动区域、显示/隐藏入口和托盘恢复能力。
- [PyInstaller 打包后的 PyQt6 体积较大] → 仅保留必要模块，并在打包阶段验证启动与资源加载。
- [本地 SQLite 文件被移动或损坏会影响数据读取] → 在启动时检测数据库可用性，并对异常做可见提示而非静默失败。
